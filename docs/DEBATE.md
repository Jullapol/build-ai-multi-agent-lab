## Brand Strategist

**จุดยืนเปิด (R1):** headline ตอนนี้ "Builder ที่ให้ทีม AI ทำงานแทน" บอกว่า JT *ทำอะไร* แต่ไม่ได้บอกว่า *คนอ่านได้อะไร* ประโยคที่มีพลังจริงไปซ่อนอยู่ใน Bio คือ "ผู้ช่วยที่ไม่ต้องจ่ายเงินเดือน" Audience ก็ขัดกันเอง PROFILE บอกว่า "ไม่ต้องสาย tech" แต่ Interests ข้อ debug กับคำว่า multi-agent พูดกับ dev → เสนอให้ **กลุ่มหลัก = คนทำงานที่งานล้นมือ** และ dev เป็นกลุ่มรอง

**ถูกท้าทายแล้วเปลี่ยน:**
- R1 เสนอ headline "ให้ทีม AI ทำงาน คุณได้กลับบ้านตรงเวลา" → `@reviewer` กับ Devil ชี้ว่าเป็นการ**สัญญาผลลัพธ์**ที่ขัดกับข้อ "ไม่เคลมเกินจริง" ใน PROFILE → R2 **ถอน** และยอมรับด้วยว่าคำว่า "ทำงาน**แทน**" เกินจริง เพราะใน Bio เองยังมีคนเช็กงานและต้องรู้ว่าเมื่อไหร่ควรหยุด
- R2 เสนอ A "ผู้ช่วยที่ไม่ต้องจ่ายเงินเดือน (แต่ต้องสอนงาน)" / B "จัดทีมผู้ช่วย AI ให้แบ่งงานกันเหมือนทีมจริง" → R3 เลือก A (B ฟังเหมือนคำโปรยคอร์สทั่วไป ไม่มีตัวตน JT) → `@reviewer` แย้งว่า A ไม่มีคำว่า AI คนอาจนึกว่าเป็นเด็กฝึกงาน → R4 ปรับเป็นเวอร์ชันสุดท้าย:
  - **Headline:** "ผู้ช่วย AI ที่ไม่ต้องจ่ายเงินเดือน (แต่ต้องสอนงาน)"
  - **Tagline:** "ผมจัดทีม AI ให้แบ่งกันจด เช็ก และเตือน แล้วมาเล่าที่นี่ว่าอะไรเวิร์ก อะไรพัง"
  - "Builder" ลดไปเป็นบรรทัดรองใต้ชื่อ · "กลับบ้านตรงเวลา" อยู่ใน Bio ต่อได้ในฐานะ*เป้าหมายของ JT เอง* ไม่ใช่คำสัญญากับคนอ่าน
- เมนู: R2 เสนอ "หน้าแรก · เกี่ยวกับผม · ผลงาน · ติดต่อ" แล้ว R3 **ยอมถอน "ผลงาน"** เพราะถ้ายังไม่มีเคสจริง เมนูนี้จะพาไปหน้าว่าง

**ยืนหยัดจนจบ:**
1. **เส้นแดง:** ห้ามเอาคำว่า "ทำงานแทน" ขึ้นเว็บ ถ้า JT ยังไม่แก้ headline ใน PROFILE ให้ถือเป็น **blocker ก่อน ship**
2. ต้องมีทางไปต่อ 1 ช่องที่เป็นของจริง (GitHub คุ้มที่สุด เพราะเป็นหลักฐานงานไปในตัว) วางไว้ท้าย About · ลิงก์ `example` ห้ามขึ้นเว็บ
3. โทนครีม / ส้มอิฐ / น้ำตาลอ่อน **เป็นตัวแบรนด์ ไม่ใช่งานตกแต่ง** (R3 ค้าน `@frontend` ที่เสนอให้ตัด) → R4 ยอมเลื่อนไปรอบหน้า โดยต้องบันทึกว่า "ค้างอยู่" ไม่ใช่ "ถูกตัดทิ้ง"
- มุกให้มีไม่เกิน 1 จุดต่อ section ส่วนความน่าเชื่อถือต้องมาจากผลงาน
- เคส "เว็บนี้เอง" ใส่ใน About ได้ 1 ประโยค **หลัง ship จริงเท่านั้น** และห้ามอ้างถึงคอร์ส
- **ไม่เห็นด้วยกับ Devil** เรื่องเปลี่ยนเป้าเว็บจาก Portfolio เป็นหน้าแนะนำตัว: เว็บที่ ship จริงแล้วคือหลักฐานชิ้นแรก

**ถึง JT:** ถ้าตัดสินได้ข้อเดียววันนี้ → **แก้ headline ใน PROFILE**

## Devil's Advocate

**ความเสี่ยง (R1 เรียงจากหนักไปเบา · `@reviewer` ตรวจกับโค้ดแล้ว):**
1. **Guestbook XSS:** `guestbook.astro:29-30` เอาค่าใส่ `innerHTML` โดยไม่ escape ส่วนข้อ "กรองข้อความก่อนแสดง" ใน PROFILE ยังไม่มีในโค้ด — *ยืนยันแล้ว*
2. **เก็บ PII โดยไม่แจ้ง:** ฟอร์ม `/contact` → `contact_messages` ไม่บอกระยะเวลาเก็บและไม่มีทางขอลบ — *reviewer: เป็นความเสี่ยงจริง แต่จะเกิดหลัง backend ใช้งานได้*
3. **Spam/abuse:** ไม่มี rate limit / honeypot / ตรวจความยาวฝั่ง server (`maxlength` มีแค่ใน HTML)
4. **ข้อความคอร์สหลุดตอน runtime:** `db.ts:55,60,68` throw `"…Lab 05 OpenCode"` → `api/contact.ts:20-21` ส่งออกไปดิบ ๆ → `contact.astro:36` / `guestbook.astro:26` แสดงบนจอ (guestbook แสดง**ตั้งแต่โหลดหน้า**) · `tests/public-site.test.ts` สแกนแค่ markup นิ่งจึงจับไม่ได้ — *reviewer: จริง และหนักกว่าที่บอก และเจอเพิ่มว่า meta description ใน `BaseLayout.astro:6` มีคำว่า "…for the multi-agent course" อยู่*
5. **Overclaim:** "ให้ทีม AI ทำงานแทน" + การ์ดผลงาน 2–3 ใบที่ยังไม่มีเคสจริง = เดโมสวย ๆ ซึ่งขัดกับ Bio ตัวเอง
6. **Credibility:** ลิงก์ `example` บนเว็บที่ขึ้นจริง ทำให้ดูเป็นเว็บปลอม

**ปะทะกับวง:**
- ตอบ reviewer (R2): PII/spam ไม่ได้ "เกินจริง" แค่ถูกเลื่อนไปอยู่ใน Lab 05 ถ้ารอบนี้ไม่ตัดสินว่าฟอร์มเปิดหรือปิด OpenCode จะเขียน `insertContact` โดยไม่มีเงื่อนไขกำกับ · dummy คือการตัดสินใจของเจ้าของที่**ขัดกับเป้าหมายของตัวเอง** เพราะคนจะรู้ใน 10 วินาทีว่าเว็บนี้ปลอม
- **Parse Contact = scope creep** (R3): แก้ `profile.ts` (ใช้ร่วมกับ `/api/interests`) เพื่อเอา `example.com` ขึ้นจอ
- **Escape อย่างเดียวไม่พอ** (R3): error ที่มีคำว่า "Lab 05" ยังขึ้นจอ → ให้ `/guestbook` ตอบ **404** และตัดลิงก์ที่ `index.astro:19`
- **เคส "เว็บนี้เอง" เสี่ยงสามชั้น** (R3): (ก) ถ้าเล่าเรื่อง handoff / owner / 20 turns ก็คือการเล่าโครงคอร์สด้วยคำอื่น guard จับไม่ได้แต่คนอ่านรู้ทัน (ข) เพื่อนร่วมคอร์สจะใช้เคสเดียวกันหมด (ค) backend ยังเป็น stub และยังไม่ได้ deploy → ใช้ได้เมื่อมี URL ที่ตอบ 200 จริงและมีตัวเลขที่วัดได้เท่านั้น
- **หันมาโจมตีฝั่งตัด** (R4): portfolio ที่ไม่มีผลงานและไม่มีทางติดต่อ = หน้า About ยาว ๆ · การที่ agent จะ override Must ของเจ้าของ 2 ข้อ (ผลงาน 2–3 การ์ด, ลิงก์ติดต่อ dummy) = **เกินอำนาจ** agent ทำได้แค่เสนอและบันทึก
- ตอบ `@frontend` (R5): การแยก Commit A/B ช่วยให้ revert ง่าย แต่**ไม่ได้ทำให้ได้รับอนุญาต** → Commit B ต้องอยู่ใน branch/PR รอ JT merge (`@reviewer` เข้าข้างข้อนี้)

**เรื่องที่ JT ต้องตัดสินเอง:** (1) ช่องทางติดต่อจริง ใช้ช่องไหน หรือจะไม่มีเลย (2) จะมีส่วนผลงานไหม ใช้ "เว็บนี้เอง" หรือรอเคสจริง (3) เป้าเว็บยังเป็น Portfolio หรือเปลี่ยนเป็นหน้าแนะนำตัว (4) headline ใหม่ (JT แก้ PROFILE เอง) (5) จะเปิดฟอร์ม/guestbook เมื่อไหร่ ใครอ่าน เก็บกี่วัน ลบยังไง

**Handoff ถึง backend (ขั้นต่ำ):** ตอบ 501 ด้วยข้อความกลางที่ไม่อ้างคอร์ส · ระหว่างที่ UI ปิด POST ต้องไม่บันทึกลง SQLite · ตรวจความยาวฝั่ง server · เปิดใช้เมื่อ JT ตอบข้อ (5) แล้วเท่านั้น

**Residual risk (R5):** `/api/*` ยังยิงตรงได้จนกว่า backend จะแก้ (ซ่อนไว้ ≠ แก้แล้ว) · ถ้า OPEN_LOOPS เรื่องช่องทางติดต่อค้างนาน เว็บจะเป็นทางตัน · ถ้าไม่มี Playwright วัดจริง เส้นแดง 360px ก็เป็นแค่คำสัญญา

**เส้นแดง:** ห้าม `example.com` หรือ "Lab 05" ขึ้นเว็บสาธารณะ ทั้งทาง UI และทางยิง API ตรง · headline T13 **ผ่าน**เกณฑ์ credibility

**ถึง JT:** ถ้าตัดสินได้ข้อเดียววันนี้ → **เลือกช่องทางติดต่อจริง 1 ช่อง (หรือประกาศว่าไม่มี)** เพราะข้อนี้ข้อเดียวกำหนดว่าเว็บนี้เป็น portfolio หรือไม่

### เสียงจาก agent ถาวร (ประกอบ ไม่ใช่มุมที่ 4)
